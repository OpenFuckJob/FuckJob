# BOSS 建联失败隔离设计

## 目标

单个岗位无法完成 BOSS 建联时，记录可诊断的失败原因并继续处理后续岗位；只有确认建联成功后，才进入对应聊天会话发送招呼。

## 范围

- 保持岗位卡片展开、规则过滤和 AI 评分流程不变。
- 不重试单个失败岗位；本轮直接跳过。
- 不将失败岗位保存为已沟通，也不打开通用聊天页作为兜底。

## 流程

1. 右侧详情面板中定位当前岗位的“立即沟通”按钮。
2. 点击按钮，并处理当前页面出现的站点确认弹窗。
3. 仅在下列任一信号出现后视为建联成功：按钮状态变为已沟通、当前页已进入该岗位的聊天输入区、取得有效的岗位专属聊天 redirect 地址。
4. 使用已确认的专属会话进入聊天并发送消息。
5. 若未获得成功信号，记录岗位标识、按钮属性和页面提示，返回单岗位失败结果。

## 错误处理

- 外层岗位循环收到单岗位失败后写入 warning 并继续，不结束本轮或周期性任务。
- 空或通用 `/web/geek/chat` redirect 地址无效，禁止打开。
- 聊天页未出现输入框视为该岗位失败，关闭临时标签并继续。

## 验收与测试

- 回归测试证明单岗位失败不会阻止下一个岗位处理。
- 回归测试证明空/通用 redirect 不会被用于打开聊天页。
- `cargo test` 与 `cargo check` 均通过。
