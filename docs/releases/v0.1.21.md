# OfferFlow v0.1.21

本版本集中修复 0.1.20 发布后暴露的稳定性问题：BOSS 未读沟通页定时加载更稳、浏览器自动化新标签不再抢前台，大模型配置草稿不再导致应用启动崩溃，Responses 流式错误也会展示可判断的上游错误码。

## BOSS 未读沟通稳定性

- 周期回复未读消息时优先复用已就绪的沟通页；只有分类标签尚未出现时才重新导航到沟通页，减少重复打开与等待。
- 补强沟通页就绪判断与等待流程，避免页面还没加载完就读取「未读」标签导致超时或误判。
- 对沟通页加载过程增加诊断、修复、评审与交付记录，便于后续继续排查同类超时问题。

## 浏览器后台标签页

- 业务新标签通过 CDP `Target.createTarget` 显式以后台方式创建，再附加到对应 target，避免 Chrome 默认把自动化标签切到前台。
- 托管浏览器启动参数改为最小化窗口但保留后台任务执行能力，避免隐藏窗口导致后台节流影响 RPA 运行。
- 新增后台标签创建与启动参数测试，守住「不抢前台、不节流后台任务」的行为。

## 配置与大模型设置

- 修复无效或未填完整的大模型配置可能阻断应用启动的问题：加载历史草稿时只做安全规整，保存时再执行严格校验。
- 半填写的主用／备用大模型配置会作为草稿安全加载，但不能持久化为可用配置；错误提示明确指出缺少地址或模型名称的服务。
- 配置迁移与前端配置面板补充回归测试，覆盖无效模型配置、备用服务草稿、onboarding 与配置页状态同步。

## 大模型错误可观测性

- Responses 流式调用返回 `error` 事件或 `response.failed` 时，会提取并展示 provider 返回的 `code`、`type` 等元数据，而不是只显示泛化错误。
- 支持 HTTP 错误体、Responses SSE 顶层错误事件、`response.error` 三种错误信封形态；`response.incomplete` 会展示截断原因。
- 错误信息会保留可诊断的错误码，同时避免把 provider 返回的敏感 message 原文直接暴露出来。

## 注意

- 本版本没有新增用户侧主流程入口，主要是稳定性与错误诊断修复。
- 大模型配置加载策略变更后，历史未填完的配置可以进入页面继续编辑，但保存时仍需补齐服务地址与模型名称。
