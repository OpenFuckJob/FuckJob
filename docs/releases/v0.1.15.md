# OfferFlow v0.1.15

本版本在上游 v0.1.14 的基础上，将大模型调用链路迁移到 Rig 框架，收敛支持的 provider，并更新官网与项目说明内容。

## 新增与改进

- **迁移到 Rig 大模型框架**：后端 LLM 服务改用 Rig 统一普通生成与流式生成链路，并按配置的 provider 分发到对应客户端，减少自维护 HTTP/SSE 实现。
- **收敛大模型 provider 支持范围**：仅保留 Anthropic、DeepSeek、OpenAI、MiniMax、Moonshot、Ollama、OpenRouter、Xiaomi MiMo 与 Z.ai；移除 LM Studio、DashScope 和通用自定义 provider 预设。其中 OpenAI 拆分为 OpenAI (Completions) 与 OpenAI (Responses) 两个独立模式。
- **Provider-aware 大模型调用**：后端根据配置分别使用 Rig Anthropic、DeepSeek、OpenAI Chat Completions、OpenAI Responses API、MiniMax、Moonshot、Ollama、OpenRouter、Xiaomi MiMo 与 Z.ai provider，不再把所有请求固定当作 OpenAI Chat Completions 调用。
- **OpenAI 双 API 支持**：OpenAI (Completions) 继续面向 `/chat/completions` 与兼容网关；OpenAI (Responses) 使用 `/responses`，方便选择 OpenAI 新版 Responses API。
- **自定义 BaseURL 支持**：初始化配置和设置页都会按所选 provider 填入默认 BaseURL，同时保留可编辑输入框，方便切换官方区域端点、私有网关或兼容代理。
- **模型列表获取能力**：设置中的模型列表获取改用 Rig `ModelListingClient`，可按 provider 从支持列表接口的服务拉取可用模型并自动去重排序；provider 暂不支持列表接口时仍可手动填写模型名称。
- **更清晰的大模型错误提示**：针对鉴权失败、模型不存在、请求受限、网络失败等场景补充用户可读提示，并保留脱敏后的内部诊断信息用于排查。
- **官网与项目说明更新**：更新 GitHub Pages 站点、README 与页面截图，补充岗位分析、模拟面试等功能介绍。

## 兼容性说明

- 旧配置中的未知 LLM provider 会迁移为 OpenAI (Completions)，并保留原 BaseURL，方便继续连接 OpenAI-compatible 网关。
- OpenAI (Completions) 与 OpenAI (Responses) 默认都使用 `https://api.openai.com/v1`；前者请求 `<base_url>/chat/completions`，后者请求 `<base_url>/responses`。
- Ollama 默认使用原生服务根地址 `http://127.0.0.1:11434`；历史 `/v1` 地址会在运行时兼容处理。
- 除 Ollama 外，其它 provider 均需要先保存 API Key；密钥仍只保存到系统凭据库或来自 `FUCKJOB_LLM_API_KEY`。
- 本版本继承 v0.1.14 的设置中心手动检查更新与 macOS 自动更新修复。
