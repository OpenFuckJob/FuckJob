# OfferFlow v0.1.19

本版本重点是让自动投递「更像人」：新增拟人化投递节奏、周期投递多时段与定时结束，同时重做大模型配置与求职设置界面，并补齐岗位详情与沟通记录展示。

## 拟人化投递

- 新增拟人化开关，提供轻度／标准／谨慎三档。不新增节奏参数，而是在既有的单轮上限、投递间隔、岗位间停顿上叠加扰动：设定 30 条时今天可能 26 条、明天 33 条，中途还会停下歇几分钟。
- 人格种子长期保存在配置中，每天由「种子 + 日期」派生当天策略：同一天内手速与休息习惯自洽，跨天自动更换，不同用户互不相同，全程确定性推导。
- 鼠标移动走贝塞尔轨迹、消息逐字符输入、页面分段滚动；取不到坐标或浏览器拒绝时回退到原有方式，不会因此让投递失败。
- 随机跳过发生在点开岗位卡片之前，避免岗位被平台标记为已查看而永久放弃。

## 周期投递时段与轮次预算

- 每日投递时段支持多段（例如 09:00–12:00 / 14:00–18:00），用 24 小时格子拖选；可设置「跑满 N 小时自动结束」。
- 时段外暂停投递但继续回复未读消息，到点自动恢复。
- 单轮投递新增预算上界（最多 N 条／M 分钟，连续失败 5 次熔断），修复关键词过宽时一轮投递连跑数小时、回复任务始终排不上的问题。
- 等待期短于轮询间隔时也会先回一轮消息再休眠；回复耗时不再撑长投递周期（改用绝对 deadline 计时）。
- 单轮投递失败不再直接终止长驻任务，连续 3 轮失败才终止。
- 旧配置的单段投递时段会自动迁移进多段列表。

## 大模型配置

- 配置面板重做：服务预设、凭据状态、模型列表、连接测试与重试超时参数分区展示。
- 新增大模型启用／停用开关。停用后配置保留，AI 功能提示「去启用」而不是要求重新配置。
- 支持主用与备用服务互换，API Key 随服务一并对调。
- 修复未填完的备用服务无法保存的死锁：校验放宽为「可以保存」，能否调用改由可用性判断，未填完的服务不会进入降级链。
- 模型列表不再随下拉开合反复发请求，仅在点击「获取模型列表」时拉取。

## 求职设置与岗位管理

- 配置中心重组为求职设置、系统能力、数据与应用三块；方案管理支持新建、复制、改名、设为默认、归档与删除。
- 岗位描述的清洗与结构化收敛到后端一处实现，岗位分析、自动回复、打招呼、语义复核与岗位过滤统一使用清洗后的正文；原文原样入库，页面改版后重新解析即可，无需重新抓取。
- 岗位详情弹窗新增「岗位详情」页签，按语义为小节配色，并展示工作地址与招聘者。
- 沟通记录改为按收发方分栏，补上头像、日期分隔与平台回执样式；修复整段消息被误判为对方发来的问题，存量会话重新同步一次即可自愈。
- 修复保存配置后不回读后端规整结果导致的显示漂移（人格种子每次保存都变、夹取类字段回显不一致）。

## 界面细节

- 抽出共享的单选卡片组件，统一分析时机、回复策略、拟人化三处的样式与文案。
- 简化拟人化强度选项，每档压缩为「档位名 + 一句说明」。

## 注意

- 过滤规则的匹配文本随 JD 清洗改变：反爬注入的类名与粘连的技能标签不再参与命中判断，规则命中结果可能与旧版略有差异。
