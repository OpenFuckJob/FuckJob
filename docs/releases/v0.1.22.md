# OfferFlow v0.1.22

本版本集中修复猎聘自动投递的关键稳定性问题：消息已填入却没有真正发出、聊天抽屉被误关、详情页关闭后白屏，以及简历投递状态误判。同时完善 DeepSeek 与 OpenAI 兼容服务的模型列表获取，减少配置模型时依赖手工填写的情况。

## 猎聘消息发送稳定性

- 消息发送只在当前聊天容器内查找输入框和发送按钮，避免误选页面搜索框或其他同名元素。
- 输入过程改为触发真实输入事件，不再用可能提前发送消息的伪造 Enter 事件；连续处理岗位时重复注入发送脚本也不会再因变量重复声明而失败。
- 发送前只关闭明确识别的「优先沟通」付费弹窗，不再误关聊天抽屉、登录或验证弹窗。
- 只有接口返回成功或页面出现新的我方消息气泡时，才确认消息已发送；没有成功证据时限制重试次数，避免重复发送。

## 猎聘简历投递与页面恢复

- 按站内沟通、站内投递和外部网申区分岗位操作，不再用同一套状态判断处理不同入口。
- 只有页面明确显示「已投递」「已投递简历」或「已申请」时，才记录简历投递成功，避免把仅打开投递入口误算为成功。
- 修复后台详情标签页绑定错误导致的 CDP 会话失效；关闭详情页前会先恢复主搜索页，避免后续流程停在白屏。

## 大模型模型列表

- DeepSeek 改为从服务端的 OpenAI 兼容 `/models` 接口获取当前可用模型，不再依赖固定模型列表。
- OpenAI 兼容服务通过原有方式获取模型失败时，会自动尝试标准 `/models` 接口；接口不可用或响应异常时给出可判断的错误，并保留手动填写模型名称的方式。
- 修复模型列表自动填入第一个候选后，再次展开下拉框无法看到完整候选的问题。
- 未填完整的主用大模型配置仍会保留为可编辑草稿；补齐服务地址和模型名称前不会启用，也不会进入调用链。

## 注意

- 本版本没有新增主流程入口，主要提升猎聘自动投递与大模型配置的可靠性。
- 外部网申仍按独立入口识别，不会因为打开外部申请页面就被记录为站内简历投递成功。
